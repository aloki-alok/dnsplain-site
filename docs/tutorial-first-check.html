How dnsplain works

Tutorial: check your first domain

In this tutorial you install dnsplain, list your domains, read what one domain's records do, and check it for problems. It takes about five minutes. You need Go 1.27 or later and an AWS account whose Route 53 holds at least one domain.

dnsplain only reads. Nothing in this tutorial changes your DNS.

1. Install

go install github.com/aloki-alok/dnsplain/cmd/dnsplain@latest

Check that it runs:

dnsplain help

2. List your domains

If the AWS CLI works on your machine, dnsplain already has access. Run:

dnsplain zones

You see one line per domain:

example.com                  ROUTE53 (aws-default)
example.org                  ROUTE53 (aws-default)

aws-default means dnsplain used your AWS CLI credentials, because it found no creds.json.

If you see an error about credentials, run aws sts get-caller-identity first. When that works, dnsplain works too.

3. See what each record is for

Pick one domain from the list:

dnsplain explain example.com

dnsplain groups the records by the job they do:

example.com  ROUTE53 · 64 records · 64 explained
  web           points to CloudFront on 2 names: @, www
  mail-in       Google Workspace receives mail on 2 names: @, alerts
  spf           Allows Google Workspace to send mail as example.com.
  dkim          Amazon SES signing keys on 33 names: ...
  dmarc         DMARC policy "none" for example.com: only reports spoofed mail, still delivers it.

A line marked unexplained is a record dnsplain doesn't recognize yet. It's shown with its raw value so nothing is hidden.

4. Check it for problems

dnsplain check example.com

For each problem, dnsplain says what's wrong, why it matters, and how to fix it:

example.com  ROUTE53
  warn      dangling   nlp.example.com
            nlp.example.com points to x-nlp.elb.ap-south-1.amazonaws.com, which doesn't exist. Visitors get an error.
            fix: Delete this CNAME, or point it at a live host.

0 critical, 1 warn, 0 info, 0 unchecked across 1 domains

When the domain is healthy, you see ok, no problems found.

5. Check everything

dnsplain check --all

Next steps

  • Create a read-only AWS policy, so dnsplain never runs with more access than it needs.
  • Run the check every day and get an alert only when something breaks.
