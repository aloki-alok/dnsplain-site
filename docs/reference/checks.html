How dnsplain works

Checks reference

Every finding has a check name, a severity, the record's name, a reason and a fix.

Severities

Severity Meaning Changes the exit code
critical Something is broken now, or anyone can take it over Yes, exit 1
warn Broken, but low risk, or close to breaking No
info Works, but weaker than it should be No
unchecked A DNS lookup failed, so the check couldn't decide No

A failed lookup is always unchecked, never a problem.

delegation

Compares the nameservers your provider says it uses with the ones the internet uses.

Finding Severity
The internet uses different nameservers, so the zone has no effect critical
The domain has no nameservers or isn't registered critical
The provider didn't report nameservers unchecked

Zones under a private name, such as corp.internal, are skipped. A private Route 53 zone under a real name, such as corp.example.com, reports no nameservers, so it shows as unchecked.

spf

Reads every SPF record (v=spf1) in the zone and follows include and redirect the way a mail receiver does.

Finding Severity
Two or more SPF records on one name critical
The record allows every server (+all or a bare all) critical
An include or redirect target has no SPF record critical
More than 10 DNS lookups critical
8 to 10 DNS lookups warn

Counted as lookups: include, redirect, a, mx, ptr and exists, including the ones inside included records. redirect is ignored when the record also has all. A macro include such as include:%{d}.spf.example.com counts as one lookup and isn't followed.

dkim

For each DKIM CNAME, asks for the signing key through your own name, the way a receiver does.

Finding Severity
The key's name doesn't exist warn

An empty key counts as present. Amazon SES publishes three keys per domain and leaves the inactive ones empty.

dmarc

Finding Severity
The domain sends mail (it has SPF, DKIM or a bounce domain) and no DMARC record answers warn
A DMARC record uses p=none info

DMARC is read from live DNS, so a _dmarc CNAME to a DMARC service counts. A subdomain zone is covered by its parent domain's DMARC.

dangling

For each CNAME that points a website name at a host, checks that the host still exists.

Finding Severity
The target is gone, and anyone can claim it on its service critical
The target is gone warn

Services where a gone target can be claimed: S3 websites, Heroku, GitHub Pages, Azure App Service and Cloud Services, Traffic Manager, Elastic Beanstalk, Netlify, Surge, Ghost, Shopify, Bitbucket, Fly and ReadMe.

Names that start with an underscore (_mta-sts, default._bimi) are skipped. They point at text-only records by design.
