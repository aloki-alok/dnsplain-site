How dnsplain works

How to connect other DNS providers

dnsplain reads any provider that dnscontrol supports. You list your accounts in a creds.json, in the same format dnscontrol uses.

Steps

  1. Create ~/.config/dnsplain/creds.json. dnsplain also reads ./creds.json in the folder you run it from.

  2. Add one entry per account. The key is a name you choose. TYPE is the provider:

    {
  "cloudflare": { "TYPE": "CLOUDFLAREAPI", "apitoken": "$CLOUDFLARE_API_TOKEN" },
  "namecheap":  { "TYPE": "NAMECHEAP", "apikey": "$NAMECHEAP_API_KEY", "apiuser": "you" },
  "aws":        { "TYPE": "ROUTE53", "Profile": "dnsplain" }
}

  3. Keep secrets out of the file. A value that starts with $ is read from that environment variable.

  4. Run dnsplain zones. You see every domain from every account.

Keys for common providers

Use the least access each provider allows.

Provider TYPE Read-only access
AWS Route 53 ROUTE53 Read-only Route 53 policy
Cloudflare CLOUDFLAREAPI API token with Zone: Read and DNS: Read
Namecheap NAMECHEAP API access must be enabled on the account, and your IP must be on its allow list
DigitalOcean DIGITALOCEAN Token with read scope

For every other provider and its fields, see dnscontrol's provider list.

Limits to know

  • GoDaddy only gives API access to accounts with 50 or more domains.
  • Hostinger has no dnscontrol provider yet. If a domain is registered at Hostinger but its nameservers point to Route 53 or Cloudflare, connect that provider instead. The records live there.
  • A provider without a "list zones" API is skipped by zones and --all, with a note. You can still name its domains one at a time.
  • An entry whose type is registrar-only (it holds no zones) is skipped.
