How to create a read-only Route 53 policy

dnsplain never writes DNS, but your AWS CLI credentials probably can. This page gives dnsplain its own credentials that can only read Route 53.

The policy

dnsplain reads through dnscontrol's Route 53 provider, which uses three read calls: ListHostedZones, ListResourceRecordSets and GetHostedZone.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DnsplainReadOnly",
      "Effect": "Allow",
      "Action": [
        "route53:ListHostedZones",
        "route53:ListResourceRecordSets",
        "route53:GetHostedZone"
      ],
      "Resource": "*"
    }
  ]
}

Steps

  1. Save the policy above as dnsplain-read.json.

  2. Create the policy:

    aws iam create-policy --policy-name dnsplain-read --policy-document file://dnsplain-read.json

  3. Create a user for dnsplain and attach the policy. Replace <account-id> with your AWS account ID:

    aws iam create-user --user-name dnsplain
aws iam attach-user-policy --user-name dnsplain --policy-arn arn:aws:iam::<account-id>:policy/dnsplain-read
aws iam create-access-key --user-name dnsplain

  4. Add a profile for those keys:

    aws configure --profile dnsplain

  5. Point dnsplain at the profile with a creds.json:

    { "r53": { "TYPE": "ROUTE53", "Profile": "dnsplain" } }

  6. Run dnsplain zones. If a call is denied, the error names the missing action. Add it to the policy and tell us, so this page stays correct.

If you use AWS SSO

Skip steps 1 to 4. Create a permission set with the same policy, then put the SSO profile name in creds.json as Profile.
