How dnsplain works

How to run a daily check with alerts

dnsplain check --all exits with code 1 when it finds anything critical. Use the exit code to alert, and stay quiet otherwise.

Option A: cron on your machine

  1. Make a script, ~/bin/dnsplain-daily-check.sh:

    #!/bin/sh
out=$(dnsplain check --all 2>&1)
code=$?
if [ "$code" -ne 0 ]; then
  printf '%s\n' "$out" | mail -s "dnsplain: DNS problems found (exit $code)" you@example.com
fi

  2. Make it executable:

    chmod +x ~/bin/dnsplain-daily-check.sh

  3. Run it every day at 08:00. Open your crontab with crontab -e and add:

    0 8 * * * $HOME/bin/dnsplain-daily-check.sh

Exit code 2 means dnsplain itself failed, for example because of expired credentials. The script alerts on that too, so a silent failure can't look like a healthy run.

Option B: GitHub Actions

  1. Store read-only AWS keys as repository secrets: AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY. See How to create a read-only Route 53 policy.

  2. Add .github/workflows/dns-check.yml:

    name: dns-check
on:
  schedule:
    - cron: "0 8 * * *"
  workflow_dispatch:
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/setup-go@v5
        with:
          go-version: "1.27"
      - run: go install github.com/aloki-alok/dnsplain/cmd/dnsplain@latest
      - run: dnsplain check --all
        env:
          AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          AWS_REGION: us-east-1

  3. The run fails on any critical finding. GitHub then emails the workflow's owner.

Only alert on new problems

Warnings you've accepted still show every day. To alert only on criticals, rely on the exit code and ignore the warning text. To track changes over time, save dnsplain check --all --json each day and compare it with yesterday's file. See the JSON output reference.
