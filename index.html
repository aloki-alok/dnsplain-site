Three commands, one picture of your DNS

Records are written for machines. dnsplain turns them back into the goals they serve, then tells you where reality doesn't match.

zones

Find every domain you own. Connect your provider accounts once and see each domain, the provider that hosts it, and the account it lives in.

explain

See what each record is for. "Amazon SES signing keys on 33 names", "points to CloudFront on @ and www", "Proves to Google that you own this domain".

check

Catch problems before they cost you. Zones the internet doesn't use, broken SPF, missing DKIM keys, mail domains with no DMARC, and CNAMEs to deleted hosts that anyone can claim.

SOA

Quiet unless it's sure

A tool that cries wolf gets ignored. A false "critical" sends someone to change DNS that was fine. So dnsplain follows three rules.

A failed lookup is "unchecked"

Timeouts and server failures never turn into findings. You see "couldn't check", with the reason.

It asks the way a receiver asks

DKIM keys are requested through your own name, exactly as a mail server does. SPF lookups are counted by the RFC's rules.

It never writes

v1 only reads. Use read-only keys: the docs give an AWS policy with exactly the three calls it needs.

A

Install and run

One Go binary. If your AWS CLI works, there's nothing else to set up. Other providers use a dnscontrol-format creds.json.

go install github.com/aloki-alok/dnsplain/cmd/dnsplain@latest
dnsplain zones
dnsplain explain example.com
dnsplain check --all

The repository is private during early access. check exits 1 on any critical finding, so it drops into cron or CI as is.
